# InfraDrishti Backend Forensic Audit & Repair

## Executive Verdict

**YELLOW**

The full analytical pipeline was audited, a critical route-diversity bug was identified and repaired, the test suite was fixed to properly authenticate, and the WDPA null-vs-zero semantics were improved. All 22 backend tests now pass. The verdict remains YELLOW rather than GREEN because the platform is limited to a single validated geographic cache (Latur–Osmanabad, Maharashtra), dynamic out-of-coverage acquisition is not wired into the synchronous API, and the WDPA protected-areas layer is empty for this AOI.

## 1. Route Diversity

- **Requested routes (n_routes):** 5
- **Returned routes:** 5
- **Valid route count:** 5 (all genuinely distinct)
- **Root cause of prior bug:** The diversity masking loop masked the **full path** (including start/end cells) with a 25-cell (1250m) radius. - **Fix applied:** Restored terminal convergence zones (60-cell / 3km margin at each end left unmasked) and reduced the mask radius from 25 to 15 cells (750m). This allows subsequent MCP solves to connect the same fixed endpoints via genuinely different corridors.

- **Hard constraint:** Configured as hard exclusion: `cost_surface[pa_data > 0] = np.inf`. Since all cells are 0, no cells are excluded. If protected areas were present, routes would be forced to avoid them.

- **Null vs zero handling:**

## 6. API Integrity

- **Request propagation:** `n_routes`, `mcda_weights`, `corridor_width_m`, `infrastructure_type`, `required_area_acres/m2`, `facility_type` — all propagated to planner/finder without loss.
- **Authenticated user:** JWT-derived via `Depends(get_current_user_id)`. User ID never taken from request body. Supabase persistence uses service-role key (bypasses RLS for trusted server operations).
- **Request ID:** Unique per request (timestamp + UUID8). No reuse observed.
- **Response schema:** Corridor returns `request_id, status, routes, infrastructure_type, corridor_width_m, n_routes, geojson, diversity_metrics, failed_attempts`. Site returns `request_id, status, sites, facility_type, required_area_m2, min_pixels, total_candidates_evaluated, geojson`.
- **GeoJSON:** FeatureCollection with LineString (corridor) or Polygon (site). EPSG:4326, `[longitude, latitude]` order. Coordinates verified numerically (~76.5/18.4, not projected metres).
- **Provenance:** Manifest records data source, cache bounds, request_id for each analysis.
- **Errors:** Structured `{error:{code,message,request_id}}`. Codes: INVALID_REQUEST, VALIDATION_FAILED, DATA_COVERAGE_BLOCKER (422), NO_VALID_ROUTE, NO_SUITABLE_SITE, PROCESSING_FAILED. No tracebacks to client.

## 10. Remaining Limitations

### Actual Bugs Remaining
- None blocking the covered corridor/site workflows.

### Data Limitations
- Coverage is a single validated cache (lon 75.80–76.81, lat 17.89–18.61). Dynamic acquisition exists as providers but is not wired into the synchronous API. Out-of-coverage returns `DATA_COVERAGE_BLOCKER` (422).
- No railway-distance or power-grid raster. Those site proximity metrics are reported as "Not available".
- WDPA protected-areas layer is empty for this AOI. Protected-area hard constraints are effectively inactive here. If a different AOI had protected areas, the hard exclusion would apply.

### Modeling Limitations
- `pop_sum_1km_sq_approx` is an approximate 2-km-kernel population sum, not exact zonal population.
- `acquisition_friction_index` is a spatial screening proxy (buildings + cropland), not ownership/probability/cost.
- `river_crossings` counts rasterized river-network cells under the route (a proxy for intersections), not actual bridge/crossing points.
- Candidate sites are planning areas (watershed-segmented contiguous regions), not legal cadastral parcels.

### Performance Limitations
- Each analysis recomputes the full cached-grid cost surface (~3.3M cells) and runs MCP via scikit-image. Corridor planning with n_routes=5 takes ~30-60s on this machine.
